> **Status:** ✅ P0-A–D implemented (Tasks 8–14). See README.

> **Later plans:** [piPy P3a — compaction, context, queues, retry](./2026-05-24-pipy-p3a.md)

**Goal:** 在 MVP 之上，使 piPy 达到与 [pi 官方文档](https://pi.dev/docs/latest) 及 `harness/pi` 对齐的「日常 coding harness」能力：完整默认工具集、会话持久化、鉴权链、`--mode json` 程序化输出。

**Architecture:** 延续 `pi_ai` → `pi_agent` → `pi_coding_agent` 三层；新增 `pi_coding_agent/session/`（JSONL 对标 `SessionManager`）、`pi_coding_agent/auth/`（对标 `AuthStorage`）、`pi_coding_agent/modes/json_mode.py`（对标 `pi --mode json`）。工具实现严格对照 `packages/coding-agent/src/core/tools/*.ts`。

**Tech Stack:** Python 3.11+、`uv` workspace、`httpx`、`jsonschema`、`pytest`、`ruff`（与 MVP 相同）

**Prerequisites:** [2026-05-23-pipy-mvp.md](./2026-05-23-pipy-mvp.md) 已完成（print 模式、`read`/`bash`、`models.json`、Anthropic/OpenAI、`-v`）。

## 1. P1 功能地图（相对 MVP）

| 优先级 | 能力 | pi 对标 | piPy 目标 |
|--------|------|---------|-----------|
| **P0-A** | `edit` / `write` / `grep` 工具 | `createCodingTools` | `tools/edit.py`, `write.py`, `grep.py` + registry |
| **P0-B** | Session JSONL + continue | [Sessions](https://pi.dev/docs/latest)、`session-manager.ts` | `session/manager.py`、`-c` / `--session` |
| **P0-C** | `auth.json` 鉴权链 | [Providers](https://pi.dev/docs/latest)、`auth-storage.ts` | `auth/storage.py`，解析顺序对齐 pi |
| **P0-D** | `--mode json` | [JSON Event Stream](https://pi.dev/docs/latest)、`docs/json.md` | `modes/json_mode.py`，stdout JSONL |
| P1-1 | `glob` / `find` / `ls` | 同上 tools | 补齐默认工具集 |
| P1-2 | `--list-models`、settings.json | Using Pi / Settings | CLI + 默认 model |
| P1-3 | OpenAI-compat `compat` 补全 | `models.md` | `supportsDeveloperRole`、空 tools 不发 |
| P1-4 | 最小交互 REPL | Using Pi interactive | 无 TUI 的 line loop + `/exit` |
| P2 | compaction、RPC、SDK、扩展 | 文档 Programmatic / Customization | 单独计划 |

**本计划实施范围：** **P0-A → P0-D**（一个可交付迭代）。P1-* 列在 §8 为后续 backlog。

## 2. P1 成功标准（可演示）

```bash
uv sync && uv run pytest

# 工具：能改文件
./pipy-test.sh -p "Add a comment to the top of README.md" --tools read,edit,write

# 会话：同目录连续两轮 + 恢复
./pipy-test.sh -p "Remember the codename ALPHA"
./pipy-test.sh -c -p "What codename did I give?"
# 或显式 --session path/to/session.jsonl

# 鉴权：与 pi 共用 ~/.pi/agent/auth.json（API key 类型）
# （配置后无需 export，若 auth.json 有对应 provider）

# JSON 模式：管道可解析
./pipy-test.sh --mode json -p "Say hi" --provider faux --model faux/test | head -5
# 每行一个 JSON 对象，含 type 字段（agent_start, message_update, ...）
```

验收：

1. **P0-A：** faux 集成测试：`edit` 修改临时文件内容可断言；`grep` 命中行；`write` 创建新文件。
2. **P0-B：** 重启进程后 `-c` 能加载上一轮 messages；JSONL 文件格式与 pi **子集兼容**（至少 user/assistant/toolResult 条目可 round-trip）。
3. **P0-C：** `resolve_auth` 顺序：`--api-key` > `auth.json` > env > `models.json` apiKey；单元测试用临时 auth 文件。
4. **P0-D：** `--mode json` 每行合法 JSON；包含 `agent_start`、`agent_end`；**不**破坏默认 text 模式（无 `--mode` 时行为与 MVP 一致）。
5. 全量 `uv run pytest` 通过；无真实 API 的 CI 仍仅用 faux。

## 4. 设计决策

| 决策 | 理由 |
|------|------|
| Session 先实现 **线性 JSONL append**，不做分支树 | pi Session 格式完整版较大；P0 只需 continue |
| `grep` 用 `rg` 子进程（与 pi 一致） | 对标 `grep.ts`；无 rg 时 pytest skip 或 fallback `grep -r` |
| `auth.json` 仅支持 `api_key` 类型 | OAuth/`/login` 放 P1+ |
| JSON mode 事件 schema 对齐 pi `AgentEvent` 名称 | 便于与官方 JSON Event Stream 文档对照 |
| `-v` 保留为人类可读 stderr；`--mode json` 为机器可读 stdout | 职责分离 |
