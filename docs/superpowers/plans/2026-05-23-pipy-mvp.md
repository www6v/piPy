# piPy 最小可运行系统 Implementation Plan

> **Status:** ✅ MVP 已完成。下一阶段见 [2026-05-23-pipy-p1.md](./2026-05-23-pipy-p1.md)。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在空仓库 `piPy` 中实现与 `harness/pi` 架构对齐的 Python 版最小可运行 coding agent：能通过 CLI 发起一次 prompt、流式输出助手回复，并执行 pi 默认 coding 工具集中的 **`read` + `bash`**（对标 `createCodingTools`）。

**Architecture:** 采用与 pi mono 相同的三层包结构（`pi_ai` → `pi_agent` → `pi_coding_agent`），MVP 仅实现 print 模式（对标 `pi -p`），跳过 TUI、AgentHarness、会话持久化与多 provider。底层用 `httpx` 调用 OpenAI Chat Completions（含 tools），agent loop 事件语义对齐 `@earendil-works/pi-agent-core`。

**Tech Stack:** Python 3.11+、`uv` workspace、`httpx`、`pydantic` v2、`jsonschema`（工具参数校验）、`pytest`、`ruff`

## 1. 参考项目（pi）功能地图

| pi 包 | 职责 | MVP 范围 | 后续阶段 |
|-------|------|----------|----------|
| `packages/ai` | 多 provider LLM API、流式、tool calling、模型注册 | **仅 OpenAI-compatible + faux 测试 provider** | Anthropic/Google/Bedrock/OAuth 等 |
| `packages/agent` | `Agent`、`agentLoop`、工具执行、事件流 | **`Agent` + `run_agent_loop` + 并行工具执行** | `AgentHarness`、Session JSONL、compaction |
| `packages/tui` | 终端差分渲染 TUI | **不做** | 可选 `rich`/`textual` 或 subprocess 调 pi-tui |
| `packages/coding-agent` | CLI、内置工具、会话/扩展 | **print 模式 + `read` + `bash`** | interactive/rpc/json、edit/write/grep/find/ls、extensions |

### 1.1 MVP 成功标准（可演示）

```bash
# 从源码运行（对标 pi-test.sh）
./pipy-test.sh -p "List files in current directory"   # 需 OPENAI_API_KEY

# 无 API key 的单元测试
uv run pytest packages/pi_ai packages/pi_agent packages/pi_coding_agent
```

验收：

1. 进程退出码 0，stdout 有最终助手文本。
2. 日志/调试模式可见 `agent_start` → `turn_start` → `message_*` → `tool_execution_*` 序列（与 pi README 一致）。
3. `read` 与 `bash` 均可被模型调用，工具结果回灌后继续生成。
4. `bash` 在 cwd 内执行、`timeout` 可选、输出截断（对标 pi `DEFAULT_MAX_LINES` / `DEFAULT_MAX_BYTES`）。
5. CI 不依赖真实 API（faux provider）。

### 1.2 明确不在 MVP

- Interactive TUI（`pi` 无 TTY 时的 print 模式已有先例）
- `AgentHarness`、JSONL session、compaction、branch summary
- 扩展系统、skills、OAuth、`--mode rpc`
- 其余内置工具（edit/write/grep/find/ls）
- 图像输入、thinking/reasoning 档位、多 provider 切换

## 3. 类型与 API 对齐（Python 侧）

### 3.1 `pi_ai` 核心类型（对标 `packages/ai/src/types.ts`）

- `Model`: `id`, `provider`, `api`, `base_url`, `context_window`, `max_tokens`, `reasoning: bool`
- `Message` roles: `user`, `assistant`, `tool_result`
- `AssistantMessage`: `content`（text blocks）、`tool_calls`、`stop_reason`、`usage`
- `Tool`: `name`, `description`, `parameters`（JSON Schema dict）
- `StreamEvent`: `text_delta`, `tool_call_delta`, `message_end`, `error`, ...

**MVP API 表面：**

```python
def get_model(provider: str, model_id: str) -> Model: ...

async def stream_simple(
    model: Model,
    context: Context,
    *,
    tools: list[Tool] | None = None,
    signal: asyncio.Event | None = None,
) -> AsyncIterator[StreamEvent]: ...

def register_faux_provider(...) -> FauxRegistration: ...
```

### 3.2 `pi_agent` 事件序列（对标 `packages/agent/README.md`）

`prompt("...")` 必须发出：

```
agent_start → turn_start → message_start/end (user)
→ message_start → message_update* → message_end (assistant)
→ [tool_execution_start → tool_execution_end → message_start/end (tool_result)]*
→ turn_end → agent_end
```

`Agent` 类方法 MVP：`prompt`, `subscribe`, `abort`, `wait_for_idle`, `state`（messages, tools, model, system_prompt）。

工具执行：**parallel** 默认（与 pi 一致）；`execute` 抛异常 → `tool_result` 带 `is_error=True`。

### 3.3 `pi_coding_agent` CLI（对标 `packages/coding-agent/src/cli/args.ts` 子集）

| 参数 | pi | piPy MVP |
|------|-----|----------|
| `-p` / `--print` | print 模式 | 支持 |
| `--model` | `provider/modelId` | 支持，默认 `openai/gpt-4o-mini` |
| `--api-key` | 覆盖 env | 支持 |
| `--system` | 系统提示 | 支持（简短 coding agent 默认） |
| `--tools` | 工具 allowlist | 支持，默认 `read,bash` |
| `-h` | help | 支持 |

**对齐 pi `bash.ts` 的 MVP 子集：**

| 能力 | pi | piPy MVP |
|------|-----|----------|
| 参数 | `command`（必填）, `timeout?`（秒） | 同左 |
| 执行 | `spawn(shell, -c, command)` + cwd | `asyncio.create_subprocess_shell`，`cwd` 固定为 session cwd |
| 取消 | `AbortSignal` → kill 进程树 | `asyncio` task cancel + `process.kill()` |
| 超时 | 可选 `timeout` 秒 | 同左，`asyncio.wait_for` |
| 输出 | stdout+stderr 合并流式累积 + 截断 + 可选 temp 全量 | 合并流式累积 + 共享 `truncate`（MVP 可省略 temp 文件路径，仅截断脚注） |
| 非零退出 | `throw Error`（含输出） | 同左，`execute` 抛异常 → `is_error` |
| TUI 渲染 / `onUpdate` 节流 | 有 | **不做**（print 模式无 UI；可选保留 `on_update` 钩子供后续 TUI） |

## 6. 设计决策记录

| 决策 | 理由 |
|------|------|
| 用 `uv` workspace 而非 poetry | 与 pi 的 npm workspaces 类似，依赖解析快 |
| MVP 仅 OpenAI API | pi-ai 有 20+ provider；先打通一条链路 |
| 参数校验用 `jsonschema` 而非 TypeBox | Python 生态；语义等价 |
| 不做 `AgentHarness` | pi 正在将 coding-agent 迁到 harness；MVP 用 `Agent` 即可跑通 |
| faux provider 优先于 VCR | 与 pi `registerFauxProvider` 一致，确定性高 |
| CLI 名 `pipy` / 模块 `pi_coding_agent` | 避免与 PyPI 上 `pi` 包冲突 |
| MVP 含 `bash` | 与 pi 默认 `createCodingTools` 一致；listing 类任务可演示 |
| `bash` 无沙箱 | MVP 与 pi 相同：在 cwd 内真实执行 shell；文档警告勿对不可信 prompt 开放 |

## 7. 风险与缓解

| 风险 | 缓解 |
|------|------|
| OpenAI API 与 pi 的 `streamSimple` 行为不一致 | 先对齐事件类型；provider 层单测 mock SSE |
| 工具 schema 与 pi 不完全一致 | 直接读 `read.ts` / `bash.ts` 复制字段 |
| `bash` 子进程僵尸/泄漏 | `asyncio` + `finally` 里 `wait`；abort 时 kill |
| 范围膨胀（想做 TUI） | 严格按 §1.2 排除列表；P1 再扩展 |
| pi 上游 API 变更 | README 注明对标 commit / 版本号 |
